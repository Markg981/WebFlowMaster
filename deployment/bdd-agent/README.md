# Dedicated Cucumber agent

This deployment executes operator-approved support code on an organization-owned host. A Node child is an execution boundary, not a sandbox for hostile tenant code. Provision a dedicated pool and token. Do not deploy support projects in the shared API or worker image.

Build the normal agent with `docker build -f Dockerfile.agent -t webflowmaster-agent:1.3.0 .`, then `docker build -f deployment/bdd-agent/Dockerfile -t webflowmaster-bdd-agent:1.3.0 .`. Both builds use committed dependency locks; no execution request installs packages. Supply only `WFM_URL`, a dedicated `WFM_AGENT_TOKEN`, and the guarded network name when starting `compose.example.yml`. Do not mount the Docker socket, host home directory, SaaS database credentials or shared worker environment. The support project and root filesystem are read-only; `/tmp` is bounded. The agent runs as `pwuser` with all capabilities dropped and no privilege escalation.

Create and enforce the network policy **before** starting an agent. The Docker example deliberately requires an existing operator-provisioned guarded network: an ordinary bridge network alone does not enforce egress. Attach the container to that network only, and enforce destination IP/port restrictions on its host firewall or egress gateway. Permit DNS to the approved resolver, the WebFlowMaster endpoint, and explicitly approved system-under-test endpoints. Deny metadata endpoints, SaaS database/Redis and other destinations. Verify blocked destinations from inside the running container. Operators using Kubernetes can apply `network-policy.example.yml` with an enforcing CNI and label the agent pod `app: wfm-bdd-agent`; its initial egress permits cluster DNS and an in-cluster WFM API only. Adapt namespaces/labels/port to the real deployment. For external WFM/SUT endpoints add narrow IP blocks or a policy-controlled egress proxy; standard NetworkPolicy has no DNS-name allowlist. Keep ingress denied and remove any other policy that broadly allows this pod's egress.

`profiles.example.json` illustrates CJS and TypeScript profiles over a separately installed `/support` project. Operator manifest fields are `id`, `label`, `provider`, `revision`, `maxDurationMs` (1,000–300,000), absolute `projectDirectory`, relative `requirePaths`/`importPaths` globs, optional `loader: "tsx"`, `maxConcurrency` (1–16), and `environment` (names only). Manifest environment entries explicitly copy those host values; request variables are World parameters and cannot define executable paths or runtime environment. Reserved agent, Node, Cucumber, database, relay and session secrets are rejected even if listed. Agent authentication is never inherited by support children.

Every support file must resolve the same real Cucumber.js **12.9.0** instance as the profile project's runtime. Install project dependencies ahead of time with `npm ci`. Nested duplicate Cucumber installations and support symlinks escaping the project fail before code loads. TypeScript projects provision `tsx` ahead of time. Project `cucumber.*` configuration, arbitrary loaders/commands, publication and file formatters cannot override the selected source. Advertised capabilities contain only ID, label, provider, revision and duration limit. Pin `revision` to an immutable reviewed support-project artifact; after changing support code, update the manifest, restart the agent, rebind tests and publish them again.

Import `sample/addition.feature` in Cucumber mode and bind to `sample-js` or `sample-ts` revision `sample-v1`. Each saved Examples row executes alone. The runtime records genuine steps/hooks, requires one complete Cucumber scenario and terminal run event, and successful child exit. Undefined, ambiguous, pending, skipped and failed results fail the run. Output is capped at 8 MiB, all attachment content at 1 MiB, and attachments at 100 text items. Only sanitized `text/plain` attachments are returned; HTML, images, binary attachments, file paths and arbitrary stdout are omitted. Text evidence is bounded and credential-redacted before transport. Timeout, cancellation and disconnect stop owned child descendants and remove the temporary run directory.

Windows uses `taskkill /T /F` plus a bounded PowerShell `Win32_Process` descendant pass for children whose root already exited. Linux uses a fresh child process group. Process credentials and operating-system permissions remain those of the dedicated agent user. Verify process cleanup and network restrictions on every supported operator host.
